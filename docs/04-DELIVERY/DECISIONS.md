# Decisions

All decisions were made on 24 Nov 2026. Reverse one only by adding a new entry that says why.

| ID | Decision | Why | Alternatives rejected |
|---|---|---|---|
| D-01 | No database, no accounts, no analytics | The report promises "no account". Every tool works client-side; rooms are ephemeral | Supabase/Postgres (nothing to store), auth (adds friction for disabled users) |
| D-02 | Two deployables (React SPA + Flask API) and an `ml/` workspace. No Rust, no microservices | Hot paths are already native (MediaPipe WASM, liblouis C). The glue language doesn't decide speed | Rust/WASM glue, Go API, per-tool services |
| D-03 | Letter classifiers run as a hand-written JS MLP (~60 lines), not TF.js or ONNX Runtime | Keeps the site light: about 100 KB of weights vs 2–10 MB of runtime. TF.js has had no stable release since Oct 2024 | TF.js (report wording), onnxruntime-web |
| D-04 | Whisper fallback runs in the browser and downloads only on opt-in (~40 MB). No server Whisper | Free hosts have 512 MB RAM; it is private; Brave needs a fallback | Always-on server faster-whisper; paid API |
| D-05 | Emotion from MediaPipe FaceLandmarker blendshapes, scored with tuned weighted rules | Reuses the vision runtime (3.7 MB model, no extra library); transparent | face-api.js (dead), @vladmandic/human (extra library + models) |
| D-06 | ISL fingerspelling recognition ships in v2, not just ASL | Indian audience; the data exists (CC BY-SA landmarks); the report lists it as next | ASL only |
| D-07 | Recognition and lookup are labelled "fingerspelling/sign recognition" and "word-by-word sign lookup", with an interpreter disclaimer | The Deaf community (WFD/WASLI) objects to "translation" claims | Calling it "sign language translation" |
| D-08 | No word-level sign recognition in v2 | Needs ~25 MB of extra models (Holistic + word model); the report does not claim it | GestureSign ONNX + Holistic |
| D-09 | Text→Sign output order: real signer video, then sign.mt pose animation, then fingerspelling. No custom 3D avatar | Real video is preferred by Deaf users; the pose API covers the rest for free; an avatar takes weeks | three.js/VRM avatar, CWASA/SiGML |
| D-10 | Sign media is licence-clean, self-hosted, tiny WebM (240p, ≤ 120 KB), about 60–80 words per language, fetched on demand | Light, offline-capable, legal | Hot-linking Lifeprint/Handspeak/Spread The Sign (terms forbid it); YouTube embeds (heavy, tracking) |
| D-11 | Add Hindi Bharati braille (liblouis `hi-in-g1.utb`) | Indian users; free in liblouis | English only |
| D-12 | Tutorials get a practice mode that reuses the recogniser | Turns static content into learning; no extra cost | Static cards only |
| D-13 | One gunicorn worker with threads; Bridge rooms kept in memory | Two-person rooms at student scale; no Redis | Redis message queue, multiple workers |
| D-14 | Personalize applies changes live, with Undo, instead of an "Apply Filters" button | Immediate feedback, fewer steps | Apply button (Lovable brief) |
| D-15 | No cross-origin isolation (COOP/COEP) | No threaded WASM is needed after D-03; keeps media and downloads simple | COEP for ORT threads |
| D-16 | Gestures come from rules on hand landmarks, not GestureRecognizer | Saves an 8.4 MB model; the rules are tunable and explainable | MediaPipe GestureRecognizer |
| D-17 | Replace the home auto-carousel with a live "one message, every way" demo | Carousels hide content and need pause controls (WCAG 2.2.2); the demo shows the product working | 3-slide carousel (report Fig 3.5.1) |
| D-18 | Free services only: Vercel Hobby, a free backend host, the free sign.mt API, gTTS, open-licence models and fonts | Hard constraint for this project | Any paid plan or key |
| D-19 | Offline braille = built-in Grade 1 table in JS; Grade 2 and Bharati need the server | Building liblouis to WASM costs time and adds size | Emscripten liblouis build |
| D-20 | Visual direction "Every way": soft violet paper, solid violet ink, magenta only for live states, Syne display + Atkinson Hyperlegible, braille-cell motif, no gradients | Avoids the generated-SaaS look of v1 and serves legibility | Gradient hero and card grid (v1) |
| D-21 | Lint with **oxlint** (react, typescript, jsx-a11y plugins), not ESLint | It ships with the Vite 8 template, is about 50× faster and covers jsx-a11y | ESLint + typescript-eslint |
| D-22 | gTTS is installed with `--no-deps` in the API image | gTTS 2.5.4 pins `click<8.2` for its CLI only, which conflicts with spaCy 3.8 (`click>=8.2.1`). The library path doesn't use click | Dropping spaCy; older spaCy |
| D-23 | Contrast is checked by `web/scripts/contrast-check.mjs` over 12 token pairs × 12 modes (AAA for High Contrast and Low Vision) and runs in CI | Puts a number on the accessibility claim; it caught the Solarized border (2.83 → fixed) | Manual checks only |
| D-24 | **No always-on server; everything on Vercel (free).** liblouis 3.39 compiled to WebAssembly runs in the browser (Grade 1, Grade 2, Bharati); gTTS fallback is a small Flask function on Vercel (`web/api/`); ISL gloss rules run in JS; Bridge is **peer-to-peer WebRTC** with the free PeerJS broker for the handshake only. `server/` stays as a self-hostable reference API and generates the liblouis golden test vectors | The Render free quota was used up and other hosts need sign-ups or cards. Vercel CDN means no cold starts, so it's fast. Braille works offline. A truly P2P Bridge strengthens the patent claim | Render (quota exhausted), Koyeb (sign-up), the firm's VPS (not allowed) |
| D-25 | The repo is **public** on the team's GitHub (RidzM/bridgify) | Team decision, 24 Nov. Note: public disclosure counts against patent novelty (RESEARCH §1); a provisional should be filed early | Private repo + passcode gate |
| D-26 | Design revision 2 (DESIGN-SYSTEM §0): app shell with a sidebar, Atkinson Hyperlegible Next only, a neutral ramp with one violet accent, composer-first home, motion tokens | An audit found template tells. Impeccable now reports 0 anti-patterns on the home page | Keep the v1 landing layout; keep Syne |
| D-27 | ML training data comes from public multi-signer sets (ML-PIPELINE §3.1 rev 2); no team recordings | The team can't record; public sets with signer IDs still allow held-out-person evaluation | Own recordings |
| D-28 | Whisper fallback uses `whisper-tiny.en` (q8 on WASM, fp32 on WebGPU) and picks WebGPU only if `requestAdapter()` returns an adapter | `navigator.gpu` exists without an adapter on many machines (found in testing: the "no available backend" crash) | whisper-base (2× download) |
| D-29 | Playwright runs every functional flow twice: Desktop Chrome and **Pixel 7** (touch, 412 px). Accessibility sweeps run on desktop across 12 modes | The team asked for phone usability to be proven, not assumed | Desktop only |
| D-30 | **Text→Sign source order:** the per-language lexicon (sign animations prepared from sign.mt and stored in the repo) → a live sign.mt request → fingerspelling. Animations use our own `.pose` reader and a compact JSON format (v1: Int16 pixel coordinates, every 2nd frame, points under 0.3 confidence dropped), about 20 KB gzip per word | Stored words work offline and don't depend on a free API being up. The `pose-format` npm package fails to import as ESM in Node, and its parser generates code at runtime, which a strict CSP blocks. Our reader is 2 KB | `pose-viewer` web component (heavy, needs `unsafe-eval`); raw `.pose` files (3× larger); videos only (few licence-clean sources) |
| D-31 | ISL gloss (word order) runs as JavaScript rules in the browser (`engines/sign/gloss.ts`), only on Latin-script input. It drops articles and "be" verbs, moves time words first, question words last and the verb to the end. The page labels it as approximate | No server (D-24). It covers the report's test sentences, with 12 unit tests | spaCy on a server (no server, heavy) |
| D-32 | **Strict Content-Security-Policy** in `web/vercel.json`: no `unsafe-eval`; `wasm-unsafe-eval` for MediaPipe and liblouis; one SHA-256 hash for the inline theme script; `connect-src` limited to sign.mt, Hugging Face, jsDelivr and PeerJS. `scripts/csp-check.mjs` fails the build if the inline script changes without updating the hash, and `scripts/serve-prod.mjs` serves the build with the production headers for testing | It blocks injected scripts. All camera, Whisper, braille and sign flows were tested under the real policy, locally and in production | No CSP; `unsafe-inline` scripts |
| D-33 | The Vercel project's root directory is `web/`, and deploys run from the repo root so `content/` is uploaded too. `.vercelignore` keeps `ml/`, `server/`, `docs/` and tooling out of the upload | `web/` imports `../content/*.json` at build time; deploying from `web/` failed because `content/` was missing | Copying content into `web/` (two copies to keep in sync) |
| D-34 | Practice mode asks only for letters the recogniser was trained on (read from the model's `labels`). ISL has no H, J or Y in its training data, so those are never asked; the page and the report text say so | A practice target the model can't recognise would always fail and feel broken | Ask all 26 letters |
| D-35 | The sign figure is drawn as a person, not a skeleton: neck and torso silhouette, arms always joined to the hands, face points and detailed hands. When the elbow is missing or implausible, a two-link solver places it, bending down and out | Raw pose data often has no elbow or wrist for the signing arm, which left hands floating near the face | Draw only the points that are present (looked broken) |
| D-36 | **React Router 7.18.5** (imports from `react-router`), replacing 6.30 | Clears two advisories reported by `pnpm audit` (open redirect via backslash in `Link`/`useNavigate`; an SSR-only issue), which would also show as alerts on the public repo. Bridgify never passes user text to `navigate`, so it wasn't exploitable, but the audit is now clean. Cost: +9 KB gzip on the entry (113 → 122 KB of 180) | Stay on 6.x (no patched 6.x release) |
| D-37 | **Bridge transport:** PeerJS on the free broker plus a same-browser BroadcastChannel path; control packets `hello`, `ping`/`pong`, `bye` and `full`; hand packets carry x and y only | Two phones connect with no server of ours; one laptop can demo it in two tabs; x and y keep the hands stream at 13.8 kbps (under 15) | Socket.IO room server (no server, D-24); x/y/z hands (over budget) |
| D-38 | **Offline caching:** precache the app shell and content (about 1.2 MB before compression); model files only in the app's own SHA-256-checked cache (no second copy in the service worker); MediaPipe/liblouis WebAssembly and sign media cache on first use; the opt-in Whisper worker is not precached; updates wait for the user to press Reload | Offline SOS, text to speech, braille and (after one use) camera tools, without making the first visit heavy or storing 11.6 MB of models twice | Precache everything (about 45 MB); no service worker |
| D-39 | **No live sign.mt requests from the app.** Text to sign uses only the stored lexicons and our own fingerspelling; sign.mt is removed from the CSP `connect-src`. The request code stays (opt-in `planSigns(…, { live: true })`) with a detector that rejects sign.mt's synthetic ASL-letter fingerspelling | Observed 24 Nov 2026 (late): sign.mt answers `403 {"message":"Access denied"}` when the Referer is another website (localhost and no-Referer requests still get 200). That is a deliberate access control, so Bridgify respects it instead of hiding the Referer or proxying. The stored lexicons were prepared once, offline, and are credited | Proxy through a Vercel function or `referrerPolicy: 'no-referrer'` (both work around the provider's block) |
