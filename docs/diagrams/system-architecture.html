Architecture · Bridgify v2

System architecture

Everything that sees or hears the user runs in the browser. The server only gets text, sign gloss and landmark packets, and it relays Bridge messages without storing them.

Privacy

What crosses the boundary

  • Out to REST: text for braille, TTS fallback and gloss; text for the sign.mt pose proxy
  • Out to /bridge: text, gloss, status packets, plus lm landmarks only when “show my hands” is on
  • In: models, wasm and sign media, fetched once and cached by ModelManager and the service worker
  • Never: camera frames, mic audio, analytics, accounts or a database

Accent

Focal paths

  • vision.worker owns HandLandmarker, FaceLandmarker and the letter MLP, shared by Sign→Text, Gesture & Emotion, Practice and Bridge
  • Frames go one at a time as transferred ImageBitmaps: the next frame is sent only after the last result returns
  • Socket.IO /bridge relays to the other room member only: max 2 per room, packet ≤ 8 KB, ≤ 40 msgs/s

Backend

Server, in one container

  • Flask 3 + Flask-SocketIO on gunicorn, debian:trixie-slim
  • liblouis 3.39 for braille tables, spaCy en_core_web_sm for ISL gloss rules
  • Pose responses disk-cached 30 days; TTS mp3 cached by sha1
  • Limits per IP: braille 60/min, TTS 20/min, pose 30/min
